# Sleazeburg 64

A top-down crime satire for the browser, made to look and sound like a Commodore 64 game: 320×200 pixels,
16 colours, sprites and SID music. Play it at https://mselin.github.io/gta-c64/ .

A version for a real Commodore 64, in 6502 assembly, is being written in its own repository,
[mselin/Sleazeburg64](https://github.com/mselin/Sleazeburg64). Play it at https://mselin.github.io/Sleazeburg64/ .

The game is plain JavaScript modules with no build step. GitHub Pages serves this folder as it is.

## Run it locally

Browsers will not load modules from `file://`, so serve the folder:

```bash
npm start
```

Then open http://localhost:8064/ . Any static file server works just as well.

## Tests

```bash
npm install
npx playwright install chromium
npm test
```

- `npm run test:unit` runs the logic tests in Node: maths helpers, city generation, playlist parsing, car
  handling, the heat system, and how people on foot look and get hit.
  It also includes a soak test: an hour of seeded, random play run without a browser, checking after every
  step that nothing has gone wrong (invalid numbers, a stuck player, runaway numbers of cars).
- `npm run test:e2e` plays the game in headless Chromium: starting, driving, police, jobs, the title-screen
  dialog, the radio and the information page. Requests to HVSC are answered with a tiny tune generated by
  the tests, so they need no network and store no music.
- `npm run lint` and `npm run format` run ESLint and Prettier.

## Layout

| Path | What it holds |
|---|---|
| `index.html` | The page: canvas, touch buttons and the information page. |
| `js/main.js` | Entry point: builds the world, wires up input, runs the frame loop. |
| `js/config.js` | Constants and all the game's text. |
| `js/state.js` | Shared game state (`G`), the player (`P`) and message helpers. |
| `js/world.js`, `js/worldview.js` | City generation and collision queries; drawing the map. |
| `js/cars.js`, `js/peds.js`, `js/player.js` | Car handling and AI, pedestrians and police on foot, the player. |
| `js/heat.js`, `js/missions.js`, `js/spawner.js`, `js/items.js` | Wanted level, jobs, populating the streets, bullets and pickups. |
| `js/game.js`, `js/render.js`, `js/input.js` | Per-frame update, drawing, keyboard and touch. |
| `js/endings.js` | The game-over and victory screens. |
| `js/icons.js` | Pixel-art icons for the touch-screen buttons. |
| `js/help.js`, `js/glyphs.js` | What the game says about its controls, for keyboards and for touch screens; the font's letter shapes. |
| `specs/` | Feature specs. [Playing on a phone](specs/touch-controls.md) lists every touch-screen requirement and the tests for each. |
| `assets/` | Picture files: the two end screens. |
| `js/screen.js`, `js/font.js`, `js/sprites.js`, `js/audio.js` | Canvas, bitmap font, sprites, sound effects and the built-in tune. |
| `js/figures.js` | People on foot as pixel art: passers-by, police, scooter riders, cultists and the player. |
| `js/playlist.js`, `js/radio.js`, `js/info.js` | Playlist parsing, the radio, the information page. |
| `js/presence.js` | Optional Discord Rich Presence: tells the presence bridge what the game is doing. Off by default. |
| `terms.html`, `privacy.html` | Terms of use and privacy policy, linked from the game and from the Discord application. |
| `tools/presence-bridge/` | The presence bridge: a small Go program players can run to show the game on their Discord profile. See its README. |
| `sidplayer.js` | Bridge between the radio and the SID player. |
| `usbsid-player/` | USBSID-Player, the WebAssembly SID player. See its README. |
| `radio/` | The radio playlist. See its README for how to add tunes. |
| `tests/` | Unit tests, browser tests and a small static server. |

`world.js`, `playlist.js`, `cars.js` and the other game-logic modules do not touch the page when imported,
which is what lets the unit tests run them in Node.

## Discord Rich Presence

Players can choose to show what they are doing in the game on their Discord profile. A web page cannot talk
to Discord itself, so this needs the [presence bridge](tools/presence-bridge/), a small program the player runs
on their own computer. The setting is on the information page and is off by default; until a player switches
it on, the game makes no request to their computer. The bridge's README covers installing it, what it sends,
and its [code signing policy](tools/presence-bridge/CODE_SIGNING_POLICY.md).
